# Contributing to Photo Organizer

Thanks for your interest in contributing. This document covers everything you need to get started.

---

## Before you start

- **For bugs** — open an Issue using the Bug Report template
- **For feature ideas** — start a Discussion in the Ideas category before writing any code
- **For significant changes** — open an Issue first so we can agree on the approach

Small fixes (typos, obvious bugs, docs) can go straight to a PR.

---

## Development setup

### Requirements

- Linux (Ubuntu 24.04 recommended)
- Python 3.10+
- ffmpeg (`sudo apt install ffmpeg`)

### Clone and install

```bash
git clone git@github.com:moffabr1/photo_organizer.git
cd photo_organizer
bash setup.sh
source venv/bin/activate
python main.py
```

---

## Workflow

### 1. Fork the repo

Click **Fork** on GitHub, then clone your fork:

```bash
git clone git@github.com:YOUR_USERNAME/photo_organizer.git
cd photo_organizer
```

### 2. Create a branch

```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/bug-description
```

### 3. Make your changes

Keep changes focused — one feature or fix per PR. Test manually before submitting.

### 4. Commit

Write clear commit messages that explain what changed and why:

```bash
git add .
git commit -m "Add crop tool to enhancement panel"
```

### 5. Push and open a PR

```bash
git push origin feature/your-feature-name
```

Open a PR against `main` on GitHub. In the description explain:
- What you changed
- Why you changed it
- How you tested it

## Guidelines

**Keep the philosophy intact**
The app never moves, copies, or imports files. The filesystem is always the source of truth. Don't break that.

**Don't commit**
- `venv/` — regenerated by setup.sh
- `*.db` files — user data
- Thumbnail cache files
- Personal changes to `config.json`

**Code style**
- Follow the existing patterns in each file
- Keep UI logic in `main_window.py`, not in model/view files
- Background work goes in QThread or QThreadPool — never block the main thread

**Test with a real photo library**
The app is designed for large libraries. Test with enough images to exercise the async loading and caching.

---

## What we won't merge

- Cloud sync features
- AI tagging or face recognition
- RAW processing pipeline
- Anything that requires moving or duplicating files as part of normal operation
- Windows or macOS specific code without a maintainer for that platform
